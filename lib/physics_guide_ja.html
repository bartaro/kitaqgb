KITAQGB 2D + 3D AABB Deterministic Integer Solver

物理ライブラリ解説

このページは lib/physics2d.* と lib/physics3d.* の実装内容をもとに、 API・使い方・内部処理・チューニング項目を日本語でまとめたドキュメントです。

検証済みコマンド: コンパイル警告 0 / エラー 0

1. 最短導入

ビルド例

kitaqgb main.c lib/physics2d.c lib/physics3d.c -I lib -o game.gb --profile=dev

ヘッダ読み込み

#include "physics2d.h"
#include "physics3d.h"

重要ルール

inv_mass_q8 == 0 は静的ボディ（実質無限質量）です。

inv_mass_q8 > 0 は動的ボディです。

2. API 概要

2D API

シンボル役割補足
KQBody2Dボディ状態位置・速度・半径（半サイズ）・逆質量・active フラグ。
KQWorld2Dワールド設定ボディ配列・重力・反復回数・速度上限。
kq2d_world_init初期化gravity_y=32, solver_iterations=4, max_speed=512 を設定。
kq2d_overlap_aabb重なり判定2 つの AABB が重なれば 1。
kq2d_step1 ステップ更新積分 → ペア解決（反復）。

3D API

シンボル役割補足
KQBody3Dボディ状態3 軸の位置・速度・半サイズ・逆質量。
KQWorld3Dワールド設定3 軸重力と反復解決設定。
kq3d_world_init初期化gravity_y=24, solver_iterations=4, max_speed=512 を設定。
kq3d_overlap_aabb重なり判定3 軸 AABB 判定。
kq3d_step1 ステップ更新積分 → ペア解決（x/y/z）。
kq3d_dot_q8_8内積ラッパ内部で __sdot3_q8_8 を呼びます。

3. フレーム処理フロー (Mermaid)

以下は kq2d_step / kq3d_step 共通の処理順です。

flowchart TD
      A[Step(world)] --> B{world and bodies valid?}
      B -- No --> Z[Return]
      B -- Yes --> C[Loop bodies i]
      C --> D{active and inv_mass_q8 > 0?}
      D -- No --> C
      D -- Yes --> E[Apply gravity]
      E --> F[Clamp velocity by max_speed]
      F --> G[Integrate position]
      G --> C
      C --> H[iterations = max(1, solver_iterations)]
      H --> I[Repeat iterations]
      I --> J[Loop pair i,j]
      J --> K{Both active?}
      K -- No --> J
      K -- Yes --> L[Overlap check]
      L --> M{Overlapping?}
      M -- No --> J
      M -- Yes --> N[Compute penetration and split correction by inverse mass]
      N --> O[Resolve axis velocity simply]
      O --> J
      J --> I
      I --> Z

6. 使用例

2D サンプル

#include "physics2d.h"

static KQBody2D g_bodies2d[8];
static KQWorld2D g_world2d;

void game_init_2d() {
    kq2d_world_init(&g_world2d, g_bodies2d, 8);
    g_world2d.gravity_y = 24;
    g_world2d.solver_iterations = 3;
    g_world2d.max_speed = 320;

    g_bodies2d[0].x = 40;
    g_bodies2d[0].y = 24;
    g_bodies2d[0].half_x = 4;
    g_bodies2d[0].half_y = 4;
    g_bodies2d[0].inv_mass_q8 = 256; /* 1.0 */
    g_bodies2d[0].active = 1;
}

void game_tick_2d() {
    kq2d_step(&g_world2d);
}

3D サンプル

#include "physics3d.h"

static KQBody3D g_bodies3d[6];
static KQWorld3D g_world3d;

void game_init_3d() {
    kq3d_world_init(&g_world3d, g_bodies3d, 6);
    g_world3d.gravity_y = 18;
    g_world3d.solver_iterations = 2;
    g_world3d.max_speed = 280;
}

void game_tick_3d() {
    kq3d_step(&g_world3d);
}

7. チューニング指針

CPU コスト: おおむね body_count^2 * solver_iterations に比例します。

GB 向けの目安: active body は 8〜24 体程度から始めるのが安全です。

安定化ポイント:

  • 壁や地形は inv_mass_q8 = 0 を使う。
  • max_speed を適切に制限して過大な移動を防ぐ。
  • 食い込みが残るなら solver_iterations を増やす。

8. 現時点の制約

  • AABB のみ（円・カプセル・多角形 SAT は未対応）。
  • 角運動なし（トルク・スピン・慣性テンソルなし）。
  • 衝突応答は軽量重視の簡易版（軸方向の平均化・ゼロ化）。
  • KQBody2D.restitution_q8 は現状予約フィールドです（solver 未使用）。

9. CGB タイル API とパレット補助

これらの補助ライブラリは、物理結果に応じて色付き HUD、衝突マーカー、状態変化のパレット切り替えを出したい時に使います。

cgb_tile.h 側のタイル API は compiler intrinsic です。正規のエントリ名は __settile... 系です。パレット API は cgb_palette.c の通常ライブラリ関数です。

追加ファイルとビルド

#include "cgb_tile.h"
#include "cgb_palette.h"

kitaqgb main.c lib/physics2d.c lib/physics2d_circle.c \
  lib/physics3d.c lib/cgb_tile.c lib/cgb_palette.c \
  -I lib -o game.gb --profile=dev

タイル属性バイト

ビット意味用途
0..2BG パレット番号0..7 の色番号を選択します。
3VRAM バンクタイルデータのバンク 0 / 1 を選びます。
5X 反転左右反転です。
6Y 反転上下反転です。
7優先度必要に応じてスプライトより後ろへ回します。

設定フロー (Mermaid)

flowchart LR
        A[タイル番号を決める] --> B[属性バイトを決める]
        B --> C[__settilecgb または bulk helper で書く]
        C --> D[RGB555 色を作る]
        D --> E[BG または OBJ パレットへ書く]
        E --> F[CGB 上で色付きタイルが表示される]

Bank 0 / Bank 1 / Palette RAM の関係 (SVG)

パレット位置の式 (MathML)

slot = 4⋅p+c byteIndex = 2⋅slot

ここで p はパレット番号 0..7、c は色番号 0..3 です。 補助ライブラリ側で BCPS / OCPS 用の正しいオフセットへ変換します。

タイル属性バイトは KQ_CGB_ATTR(palette, bank, xflip, yflip, priority) を使うと、ビット詰めを手書きせずに組み立てられます。 よく使う形向けに KQ_CGB_ATTR_PAL(n)、KQ_CGB_ATTR_XFLIP_IF(flag)、 KQ_CGB_ATTR_PRIORITY_IF(flag) のような短縮マクロも使えます。

主要 API

API役割DMG 時の挙動
KQ_CGB_ATTR, KQ_CGB_ATTR_PALpalette / bank / 反転 / priority のビットを attr 1 バイトへ詰めたり合成したりします。コンパイル時ヘルパーです。
__settileattrCGB 属性バイトだけを書きます。何もしません。
__settilecgbタイル番号を書き、その後 CGB なら属性も書きます。タイル番号だけ有効です。
__settilecgb_bulk_fastタイル番号と属性を高速一括書き込みします。タイル番号だけ有効です。
cgb_bg_rgbRGB555 成分から BG パレット 1 色を書き換えます。何もしません。
cgb_bg_colorpacked u16 から BG パレット 1 色を書き換えます。何もしません。
cgb_bg_paletteBG パレット 1 本分 4 色を読み込みます。何もしません。
cgb_obj_paletteOBJ パレット 1 本分 4 色を読み込みます。何もしません。

使用例

#include "cgb_tile.h"
#include "cgb_palette.h"

static u16 hud_palette[4];

static const u8 hud_tiles[4] = { 0x30, 0x31, 0x32, 0x33 };
static const u8 hud_attrs[4] = {
    KQ_CGB_ATTR_PAL(2),
    KQ_CGB_ATTR_PAL(2),
    KQ_CGB_ATTR_PAL(2) | KQ_CGB_ATTR_XFLIP_IF(1),
    KQ_CGB_ATTR(2, 0, 0, 1, 0)
};

void init_hud() {
    hud_palette[0] = cgb_rgb15(31, 31, 31);
    hud_palette[1] = cgb_rgb15(31, 24, 8);
    hud_palette[2] = cgb_rgb15(14, 7, 2);
    hud_palette[3] = cgb_rgb15(1, 1, 1);

    cgb_bg_palette(2, hud_palette);
    __settilecgb_bulk_fast(0x9800 + (32 * 2) + 4, hud_tiles, hud_attrs, 4);
}
属性専用 API とパレット API は DMG では何もしません。タイル番号と属性をまとめて書く API は、DMG でもタイル番号側だけは有効です。
--cgb=cgb_only でビルドすると、tile intrinsic 側の __cgb_is_cgb() ガードはコンパイラが削除し、builtin 自体も 1 に定数化します。
ROM 常駐の定数パレット表にしたい場合は 0x7FFF のような packed 整数リテラルを使ってください。現状の静的初期化子は算術マクロより整数リテラルを好みます。
KQ_CGB_ATTR(...) と短縮マクロ群は、グローバル static 初期化子でも使えるようになりました。ROM 常駐の属性テーブルでもそのまま利用できます。
タイル intrinsic は __settile... 系の名前のみを使います。
