KITAQGB 2D + 3D AABB Deterministic Integer Solver

Physics Library Guide

This page describes the physics libraries implemented in lib/physics2d.* and lib/physics3d.*, including API usage, internal behavior, tuning points, and limits.

Validated build command: no warnings, no errors.

1. Quick Start

Build

kitaqgb main.c lib/physics2d.c lib/physics3d.c -I lib -o game.gb --profile=dev

Headers

#include "physics2d.h"
#include "physics3d.h"

Main Rule

inv_mass_q8 == 0 means static body (infinite mass).

Any positive value means dynamic body.

3. Data Flow (Mermaid)

This is the per-frame flow used by both kq2d_step and kq3d_step.

flowchart TD
      A[Step(world)] --> B{world and bodies valid?}
      B -- No --> Z[Return]
      B -- Yes --> C[Loop bodies i]
      C --> D{active and inv_mass_q8 > 0?}
      D -- No --> C
      D -- Yes --> E[Apply gravity]
      E --> F[Clamp velocity by max_speed]
      F --> G[Integrate position]
      G --> C
      C --> H[iterations = max(1, solver_iterations)]
      H --> I[Repeat iterations]
      I --> J[Loop pair i,j]
      J --> K{Both active?}
      K -- No --> J
      K -- Yes --> L[Overlap check]
      L --> M{Overlapping?}
      M -- No --> J
      M -- Yes --> N[Compute penetration and split correction by inverse mass]
      N --> O[Resolve axis velocity simply]
      O --> J
      J --> I
      I --> Z

6. Usage Patterns

2D Example

#include "physics2d.h"

static KQBody2D g_bodies2d[8];
static KQWorld2D g_world2d;

void game_init_2d() {
    kq2d_world_init(&g_world2d, g_bodies2d, 8);
    g_world2d.gravity_y = 24;
    g_world2d.solver_iterations = 3;
    g_world2d.max_speed = 320;

    g_bodies2d[0].x = 40;
    g_bodies2d[0].y = 24;
    g_bodies2d[0].half_x = 4;
    g_bodies2d[0].half_y = 4;
    g_bodies2d[0].inv_mass_q8 = 256; /* 1.0 */
    g_bodies2d[0].active = 1;
}

void game_tick_2d() {
    kq2d_step(&g_world2d);
}

3D Example

#include "physics3d.h"

static KQBody3D g_bodies3d[6];
static KQWorld3D g_world3d;

void game_init_3d() {
    kq3d_world_init(&g_world3d, g_bodies3d, 6);
    g_world3d.gravity_y = 18;
    g_world3d.solver_iterations = 2;
    g_world3d.max_speed = 280;
}

void game_tick_3d() {
    kq3d_step(&g_world3d);
}

7. Practical Tuning

CPU cost: roughly proportional to body_count^2 * solver_iterations.

Default-safe range for GB-class targets: 8 to 24 active bodies per world.

Stability tips:

  • Use inv_mass_q8=0 for level geometry and walls.
  • Keep max_speed bounded to avoid tunneling and overflow risk.
  • Raise solver_iterations only when overlap correction looks too soft.

8. Current Limits

  • AABB only (no circles, no capsules, no SAT poly solver).
  • No angular dynamics (no torque/spin/inertia tensor).
  • Contact response is intentionally simple (velocity averaging/zeroing by axis).
  • KQBody2D.restitution_q8 exists but is currently reserved and not consumed by the solver.

9. CGB Tile and Palette Helpers

These companion libraries are useful when the physics layer needs visible CGB feedback such as colored HUD tiles, collision markers, or palette swaps tied to gameplay state.

The tile-side APIs declared in cgb_tile.h are compiler intrinsics. Their canonical entry points use the __settile... naming scheme. The palette-side APIs remain normal library functions in cgb_palette.c.

Files and Build

#include "cgb_tile.h"
#include "cgb_palette.h"

kitaqgb main.c lib/physics2d.c lib/physics2d_circle.c \
  lib/physics3d.c lib/cgb_tile.c lib/cgb_palette.c \
  -I lib -o game.gb --profile=dev

Tile Attribute Bits

BitMeaningCommon Use
0..2BG palette number0..7 palette select on CGB.
3VRAM bankSelect tile data bank 0 or 1.
5X flipMirror the tile horizontally.
6Y flipMirror the tile vertically.
7PriorityPush tile behind sprites when needed.

Setup Flow (Mermaid)

flowchart LR
        A[Choose tile ids] --> B[Choose attr bytes]
        B --> C[Write map with __settilecgb or bulk helper]
        C --> D[Pack RGB555 colors]
        D --> E[Load BG or OBJ palette]
        E --> F[Visible colored CGB tile]

Bank 0 / Bank 1 / Palette RAM (SVG)

Palette Address Math (MathML)

slot = 4⋅p+c byteIndex = 2⋅slot

Here p is the palette index 0..7 and c is the color index 0..3. The helper library converts that into the correct BCPS/OCPS byte offset.

Use KQ_CGB_ATTR(palette, bank, xflip, yflip, priority) to build a tile attribute byte without hand-packing the bit fields. For the common cases, the header also exposes short forms such as KQ_CGB_ATTR_PAL(n), KQ_CGB_ATTR_XFLIP_IF(flag), and KQ_CGB_ATTR_PRIORITY_IF(flag).

Key APIs

KQ_CGB_ATTR, KQ_CGB_ATTR_PALPack or compose palette/bank/flip/priority bits into one attr byte.Compile-time helper.

Example

#include "cgb_tile.h"
#include "cgb_palette.h"

static u16 hud_palette[4];

static const u8 hud_tiles[4] = { 0x30, 0x31, 0x32, 0x33 };
static const u8 hud_attrs[4] = {
    KQ_CGB_ATTR_PAL(2),
    KQ_CGB_ATTR_PAL(2),
    KQ_CGB_ATTR_PAL(2) | KQ_CGB_ATTR_XFLIP_IF(1),
    KQ_CGB_ATTR(2, 0, 0, 1, 0)
};

void init_hud() {
    hud_palette[0] = cgb_rgb15(31, 31, 31);
    hud_palette[1] = cgb_rgb15(31, 24, 8);
    hud_palette[2] = cgb_rgb15(14, 7, 2);
    hud_palette[3] = cgb_rgb15(1, 1, 1);

    cgb_bg_palette(2, hud_palette);
    __settilecgb_bulk_fast(0x9800 + (32 * 2) + 4, hud_tiles, hud_attrs, 4);
}
Attr-only APIs and palette APIs no-op on DMG. Combined tile+attr APIs still write the tile-number side so one code path can serve both DMG and CGB.
If you build with --cgb=cgb_only, the compiler removes the runtime __cgb_is_cgb() guard from tile intrinsics and constant-folds the builtin to 1.
If you want ROM-resident constant palette tables, use plain packed literals such as 0x7FFF. Static initializers currently prefer integer literals over arithmetic macros.
KQ_CGB_ATTR(...) and the short-form attr macros now work in global static initializers, so ROM-resident attr tables can use the helpers directly.
Tile intrinsics now use the __settile... names only.
