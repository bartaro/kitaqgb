# wire3d_dmg：ゲームボーイ用モノクロ3D

`wire3d_dmg` は、ゲームボーイ向けのモノクロ・ワイヤーフレーム描画ライブラリです。3D座標を画面へ投影し、物体の辺を線で描くライブラリです。カラー専用版 `wire3d_cgb` は、従来の名前のまま別に使用します。

## ビルド前に画面サイズを選ぶ

| 項目 | 128×96 | 128×120（既定） |
| --- | --- | --- |
| ビルドするソース | `lib/wire3d_dmg_96.c` | `lib/wire3d_dmg.c` |
| ヘッダーの前で指定 | `#define WIRE3D_DMG_HEIGHT 96` | `#define WIRE3D_DMG_HEIGHT 120` |
| `Wire3DDMG_BeginFrame()` | 描画バッファと隠線判定の状態を消去 | 隠線判定の状態を初期化。画素は転送時に消去 |
| 固有機能 | HUD、角度別の辺マスク | 差分転送、補助転送 |
| モデルの上限 | 頂点24、辺16、面16 | 頂点24、面16。モデルの辺数に16本の制限はなし |

レンダラーの入口は必ず一つだけビルドしてください。ヘッダーを使うすべてのファイルで同じ高さを指定します。モデル構造体や一部の角度引数の型が設定によって異なります。選択はコンパイル時に済むため、描画中に画面サイズを判定する分岐は増えません。

## 最初のプログラムをビルドする

`kitaqgb.exe` のあるリポジトリ直下でPowerShellを開き、次を実行します。

```powershell
# 128×96で回転する立方体。
.\kitaqgb.exe lib/wire3d_dmg_96.c examples/wire3d_dmg_96.c -I lib -o examples/wire3d_dmg_96.gb --profile=dev --stack-bank=fixed --rst-disable --no-disasm

# 128×120で中央に十字を表示。差分転送を使用。
.\kitaqgb.exe lib/wire3d_dmg.c examples/wire3d_dmg_120.c -I lib -o examples/wire3d_dmg_120.gb --profile=dev --stack-bank=fixed --rst-disable --no-disasm

# 隣にkokuraリポジトリがある場合の実行と画像保存。
..\kokura\kokura-cli.exe examples/wire3d_dmg_120.gb --run-frames 120 --png examples/wire3d_dmg_120.png
```

最初のソースが画面サイズを選び、次のソースがゲーム本体です。`-I lib` はヘッダーの検索先、`-o` は出力ROMを指定します。`--stack-bank=fixed` はレンダラーが使うWRAM領域とスタックを分ける指定です。残りは検証時の開発用設定で、RST最適化と逆アセンブル出力を無効にしています。サンプルの図形はソース中に定義してあり、外部の画像は不要です。

## 毎フレームの処理

```c
#define WIRE3D_DMG_HEIGHT 120
#include "wire3d_dmg.h"

void main()
{
    Wire3DDMG_Init();
    Wire3DDMG_SetDirtyTransfer(1); // Enable dirty transfer in the 120-line profile.
    while (1) {
        Wire3DDMG_BeginFrame();
        Wire3DDMG_DrawLine3D(-24, 0, 100, 24, 0, 100);
        Wire3DDMG_DrawLine3D(0, -24, 100, 0, 24, 100);
        Wire3DDMG_EndFrame();
    }
}
```

最初に一度初期化し、フレームに必要な図形を描いてから `EndFrame` で転送します。どちらの設定も転送済みの描画バッファを消すため、毎フレーム描き直してください。120行設定の `BeginFrame` は未転送の画素を消しません。差分転送は前フレームのタイルも処理して古い画素を消します。補助転送は既定で無効で、主バッファの一部を共有しています。

モデルを描く場合は `Wire3DDMG_Model` の全フィールドを初期化してください。96行版の立方体サンプルが設定例です。頂点などの配列は描画中に参照できるROMバンクへ配置します。角度は16段階で一周、`DrawModelScaled` の倍率は256が等倍です。関数ごとの契約は `wire3d_dmg.h` に記載しています。

## メモリと描画の制約

WRAM `0xD000..0xDFFF` を予約し、描画中はバンクの対応を維持してください。初期化はLCDのタイルデータとBGマップを設定し直します。他の画面処理と使用領域を調整してください。内部状態は共通の大域変数で管理され、同時呼び出しには対応しません。奥行きの許容範囲をまたぐ辺は切り詰めずに省略します。隠線処理は面の外接矩形と線上の5点を使う近似であり、画素ごとの奥行き判定ではありません。

`EndFrame` はVBlank開始を待ち、STATを確認しながら転送します。全画面転送はVBlank終了後まで続く場合があり、毎秒60フレームを保証するものではありません。新しい2バイト単位の転送処理は、ROM使用量を増やしてループとSTAT確認の回数を減らしています。描画バッファは増設していません。

## 既存プログラムとの互換性

`wire3d.c/h` は96行設定と `Wire3D_*` 名を、`dmg3d.c/h` は120行設定と `DMG3D_*` 名を残す互換用の入口です。描画処理の本体は共通です。旧ビルドコマンドをそのまま使うか、ソース・ヘッダー・関数名をまとめて移行してください。新旧の入口を同時にリンクしないでください。新規プログラムでは `wire3d_dmg` と `Wire3DDMG_*` を使います。

## 検証結果（2026年9月13日）

両サイズと両方の互換入口をビルドし、KOKURAで実行しました。転送先、転送後に消去された元データ、変更しないビット面、バッファ境界を検査し、立方体と十字の表示を確認しています。名前の正規化後、両設定を合わせた118個の関数本体が統合前の最適化済み実装と一致し、転送サイクルの増加もありませんでした。

VBlankでの測定では、旧転送から新転送へのCPUサイクルは、120行の主転送が211,696→207,780、補助転送が36,312→34,928、96行の主転送が168,656→164,164でした。各転送で調べた8条件すべてで短縮しています。転送関数単体のエミュレーター測定であり、ゲーム全体の速度や実機動作を保証する結果ではありません。
